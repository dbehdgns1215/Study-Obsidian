

# 클러스터와 노드

## 클러스터
- 여러 Elasticsearch 노드가 하나의 시스템처럼 동작하도록 묶인 단위.

## 노드
- 실행 중인 Elasticsearch 인스턴스 하나.

## 마스터 노드
- 클러스터 상태, 노드 참여/이탈, 인덱스 생성/삭제, 샤드 배치 등을 관리하는 노드.

## 마스터 후보 노드
- 마스터로 선출될 자격을 가진 노드.

## data 노드
- 실제 샤드를 저장하고 검색, 색인, 수정, 삭제, 집계 등을 수행하는 노드.

## ingest 노드
- 문서를 저장하기 전에 파싱, 필드 가공, 데이터 변환 등을 수행하는 노드.

## 조정 노드
- 검색 요청을 여러 샤드에 나눠 보내고 결과를 모아 최종 결과를 만드는 역할을 하는 노드.

## 노드 Role
- 해당 노드가 어떤 기능을 수행할 수 있는지 지정하는 설정. `master`, `data`, `ingest` 등이 있음.

## 노드 속성
- 노드에 사용자가 임의로 붙이는 추가 정보. 랙, 가용 영역 등의 정보를 표시할 때 사용.

---

# 인덱스와 문서

## 인덱스
- 관련된 문서들을 묶어 관리하는 논리적인 데이터 단위. 내부적으로 여러 샤드로 나뉨.

## 문서
- Elasticsearch에 저장되는 데이터 한 건. 일반적으로 JSON 형태.

## 필드
- 문서를 구성하는 각각의 데이터 항목.

## 매핑
- 인덱스 내부 필드의 이름, 자료형, 검색 방식 등을 정의하는 구조.

## 필드 타입
- `text`, `keyword`, `integer`, `date` 등 필드의 데이터 형식을 나타내는 타입.

## 매핑 타입
- 과거 하나의 인덱스 안에서 문서를 종류별로 나누던 중간 계층. 현재는 제거됨.

## `_source`
- Elasticsearch에 입력했던 원본 JSON 문서를 보관하는 영역.

---

# 샤드

## 샤드
- 하나의 Elasticsearch 인덱스를 실제 저장과 처리를 위해 나눈 조각.
- 샤드 하나는 사실상 하나의 Lucene 인덱스.

## 기본 샤드
- 문서가 최초로 저장되는 원본 샤드.

## 복제 샤드
- 기본 샤드의 복사본.
- 장애 대응과 검색 부하 분산에 사용됨.

## 샤드 복사본
- 기본 샤드 또는 복제 샤드 하나를 통틀어 부르는 표현.

## 미할당 샤드
- 존재해야 하지만 현재 어느 노드에도 배치되지 못한 샤드.

## 라우팅
- 특정 문서를 어느 기본 샤드에 저장할지 결정하는 과정.

---

# 샤드 배치와 이동

## 샤드 할당
- 특정 샤드 복사본을 어느 데이터 노드에 둘지 결정하는 것.

## 샤드 재배치
- 이미 한 노드에 있는 샤드를 다른 노드로 옮기는 것.

## 샤드 복구
- 다른 샤드에서 데이터를 복사해 새로운 샤드 복사본을 정상 상태로 만드는 과정.

## 재균형
- 특정 노드에 샤드가 몰리지 않도록 여러 노드 사이의 샤드 분포를 다시 맞추는 것.

## 배치 인지
- 랙이나 가용 영역 같은 장애 영역을 고려해서 기본 샤드와 복제 샤드를 분산 배치하는 기능.

## 강제 배치 인지
- 특정 장애 영역이 사라져도 남은 영역에 복제 샤드를 무조건 몰아서 만들지 않도록 제한하는 기능.

---

# 물리 인프라와 장애 영역

## 랙
- 데이터센터에서 여러 물리 서버를 꽂아두는 서버 캐비닛.
- 랙 단위로 전원이나 네트워크 장애가 발생할 수 있음.

## 가용 영역
- 클라우드 환경에서 전원, 네트워크 등이 독립적으로 구성된 장애 영역.

## 장애 영역
- 하나의 장애가 동시에 영향을 줄 수 있는 물리적 또는 논리적 범위.
- 랙, 가용 영역, 데이터센터 등이 해당할 수 있음.

# Lucene 내부 구조

## Lucene
- Elasticsearch 내부에서 실제 색인과 검색을 수행하는 검색 라이브러리.

## Lucene 인덱스
- Lucene이 문서와 검색용 자료구조를 저장하는 단위.
- Elasticsearch의 샤드 하나가 사실상 하나의 Lucene 인덱스.

## 세그먼트
- Lucene 인덱스를 구성하는 더 작은 저장 단위.
- 하나의 Lucene 인덱스 안에 여러 세그먼트가 존재할 수 있음.

## 세그먼트 병합
- 여러 개의 작은 세그먼트를 더 큰 세그먼트로 합치는 작업.

## 역색인
- `단어 → 해당 단어를 가진 문서` 형태로 저장해 빠른 검색을 가능하게 하는 자료구조.

## 도큐먼트 값
- `문서 → 값` 형태로 저장하는 열 기반 자료구조.
- 정렬과 집계 등에 주로 사용됨.

## 저장 필드
- 검색 후 실제 필드 값을 다시 가져오기 위해 Lucene에 별도로 저장하는 데이터.

# 텍스트 검색

## 분석기
- 문자열을 검색 가능한 형태로 가공하는 전체 처리 과정.

## 토큰
- 분석 결과 만들어지는 검색의 기본 단위.

## 토크나이저
- 문자열을 여러 토큰으로 나누는 역할.

## 토큰 필터
- 만들어진 토큰을 소문자화하거나 불용어를 제거하는 등 추가 가공하는 역할.

## `text`
- 문장을 분석한 뒤 전문 검색에 사용하는 문자열 타입.

## `keyword`
- 문자열 전체를 하나의 값으로 취급하는 타입.
- 정확 일치, 정렬, 집계 등에 주로 사용.

## 전문 검색
- 문장을 분석한 뒤 단어 단위로 관련 문서를 찾는 검색 방식.

## 정확 일치 검색
- 문자열 전체 값이 정확하게 일치하는지를 확인하는 검색 방식.

## 관련도 점수
- 검색어와 문서가 얼마나 관련 있는지를 나타내는 점수.

# 검색 처리

## 검색 요청
- Elasticsearch에 특정 조건의 문서를 찾도록 보내는 요청.

## 분산 검색
- 여러 샤드에서 동시에 검색한 뒤 결과를 합쳐 최종 결과를 만드는 방식.

## 분산 단계
- 조정 노드가 검색 요청을 여러 관련 샤드로 나누어 보내는 과정.

## 수집 단계
- 여러 샤드에서 받은 검색 결과를 조정 노드가 모아서 합치는 과정.

## 집계
- 데이터를 그룹화하거나 개수, 평균, 합계 등을 계산하는 기능.

## Query DSL
- Elasticsearch 검색 조건을 JSON 형태로 표현하는 검색 문법.

# 데이터 계층

## 데이터 계층
- 데이터의 사용 빈도와 보관 기간에 따라 저장 노드를 구분하는 구조.

## 핫 계층
- 최근 생성되고 읽기와 쓰기가 자주 발생하는 데이터를 저장하는 계층.

## 웜 계층
- 시간이 지나 쓰기는 줄었지만 검색은 여전히 필요한 데이터를 저장하는 계층.

## 콜드 계층
- 접근 빈도가 낮은 오래된 데이터를 상대적으로 저렴하게 보관하는 계층.

## 프로즌 계층
- 거의 사용하지 않는 장기 데이터를 검색 가능한 스냅샷 등을 이용해 저비용으로 보관하는 계층.

## 콘텐츠 계층
- 상품, 문서, 기사처럼 시간이 지나도 검색 가치가 크게 변하지 않는 데이터를 저장하는 계층.

## 인덱스 생명주기 관리
- 시간이나 조건에 따라 인덱스를 핫 → 웜 → 콜드 → 삭제 등의 단계로 자동 관리하는 기능.

# 클러스터 구성

## 디스커버리
- Elasticsearch 노드가 다른 노드를 찾아 같은 클러스터에 참여하는 과정.

## `discovery.seed_hosts`
- 새로운 노드가 클러스터를 찾을 때 처음 접속해볼 마스터 후보 노드 주소 목록.

## `cluster.initial_master_nodes`
- 완전히 새로운 클러스터를 최초 생성할 때 첫 마스터 선거에 참여할 노드를 지정하는 설정.

## 클러스터 상태
- 현재 노드, 인덱스, 매핑, 샤드 위치 등 클러스터 전체의 상태 정보.

## Green 상태
- 모든 기본 샤드와 복제 샤드가 정상적으로 배치된 상태.

## Yellow 상태
- 모든 기본 샤드는 정상이나 일부 복제 샤드가 배치되지 않은 상태.

## Red 상태
- 하나 이상의 기본 샤드가 배치되지 않아 일부 데이터에 접근할 수 없는 상태.

# 저장과 색인

## Refresh
- 새로 색인된 데이터를 검색 가능한 세그먼트에 반영하는 과정.

## Refresh Interval
- 자동으로 Refresh가 수행되는 주기.

## 준실시간 검색
- 문서를 저장한 즉시가 아니라 Refresh 이후 검색 가능해지는 Elasticsearch의 특성.

## 트랜잭션 로그
- 아직 Lucene에 완전히 안전하게 반영되지 않은 변경 내용을 장애 복구를 위해 기록하는 로그.

## Flush
- 트랜잭션 로그 상태를 정리하고 Lucene의 안전한 저장 지점을 만드는 과정.

## Lucene Commit
- 현재 Lucene 세그먼트 상태를 디스크에 안전한 커밋 지점으로 기록하는 작업.

## 소프트 삭제
- 문서를 즉시 물리 삭제하지 않고 삭제 표시를 남긴 뒤 이후 세그먼트 병합 과정에서 실제 제거하는 방식.

---

# 디스크 관리

## 수위 기준
- 노드의 디스크 사용량에 따라 샤드 할당과 재배치를 제어하는 기준.

## 낮은 수위
- 디스크 사용량이 높아져 새로운 샤드를 해당 노드에 배치하지 않기 시작하는 기준.

## 높은 수위
- 디스크 사용량이 더 높아져 기존 샤드를 다른 노드로 이동시키기 시작하는 기준.

## 홍수 단계
- 디스크 공간이 거의 소진되어 데이터 보호를 위해 인덱스 쓰기를 제한할 수 있는 단계.

# 통신

## HTTP 포트
- 애플리케이션이나 사용자가 Elasticsearch REST API에 접근할 때 사용하는 포트.
- 일반적으로 `9200`.

## 전송 포트
- Elasticsearch 노드끼리 내부 통신할 때 사용하는 포트.
- 일반적으로 `9300`.

## REST API
- HTTP를 통해 Elasticsearch에 문서 저장, 검색, 수정, 삭제 등의 요청을 보내는 인터페이스.

## Bulk API
- 여러 문서의 저장, 수정, 삭제를 하나의 요청으로 묶어 처리하는 API.

# 백업과 원격 클러스터

## 스냅샷
- Elasticsearch 인덱스와 클러스터 데이터를 외부 저장소에 백업하는 기능.

## 검색 가능한 스냅샷
- 스냅샷 데이터를 완전히 복구하지 않고도 검색할 수 있도록 하는 기능.

## 클러스터 간 검색
- 여러 Elasticsearch 클러스터의 데이터를 하나의 검색 요청으로 조회하는 기능.

## 클러스터 간 복제
- 한 Elasticsearch 클러스터의 인덱스를 다른 클러스터로 지속적으로 복제하는 기능.

## 원격 클러스터 클라이언트 역할
- 다른 Elasticsearch 클러스터와 통신할 수 있도록 하는 노드 역할.

# 기타 노드 역할

## 머신러닝 노드
- Elasticsearch의 이상 탐지 등 머신러닝 기능을 수행하는 노드.

## 변환 노드
- 기존 데이터를 집계하거나 형태를 변경해 새로운 형태의 인덱스를 만드는 작업을 수행하는 노드.
