
## 1. 시스템 인프라 아키텍처 (클러스터 계층)

## 1.1 메타데이터 관리 시스템

## 주키퍼 (ZooKeeper)
과거 카프카 외부에서 메타데이터를 관리하던 별도의 분산 코디네이터 프로그램.

## 크래프트 (KRaft)
최신 카프카 내부에 내장된 라이브러리 형태의 메타데이터 관리 시스템.

## 1.2 클러스터 통제 엔진

## 액티브 컨트롤러 (Active Controller)
클러스터의 모든 인사권과 행정 업무를 독점하는 단 한 명의 총대장.

## 스탠바이 컨트롤러 (Standby Controller)
액티브 컨트롤러가 쓰러지면 왕위를 이어받기 위해 메타데이터를 복제하며 대기하는 조장들.

## Raft 합의 알고리즘
스탠바이들이 모여 민주적인 과반수 투표로 새로운 액티브 컨트롤러를 선출하는 기술적 원리.

## 2. 데이터 저장 구조 및 신뢰성 (스토리지 계층)

## 2.1 논리적/물리적 데이터 저장 단위

## 토픽 (Topic)
카프카에서 데이터를 구분하기 위해 사용하는 가장 큰 단위.

## 파티션 (Partition)
대량의 트래픽 처리와 분산 저장을 위해 하나의 토픽을 여러 조각으로 쪼갠 최소 단위.

## 2.2 고가용성 및 복제 아키텍처

## 리더 파티션 (Leader Partition)
프로듀서/컨슈머와 직접 소통하며 모든 데이터의 읽기/쓰기 실무를 전담하는 대장 파티션.

## 팔로워 파티션 (Follower Partition)
읽기/쓰기는 안 하고 오직 리더의 데이터만 부지런히 복사하며 대기하는 복제본.

## 리플리케이션 팩터 (Replication Factor)
원본을 포함하여 클러스터에 존재해야 하는 총 복사본의 개수.

## ISR (In-Sync Replicas)
리더의 진도를 성실하게 100% 잘 따라오고 있어 차기 리더 자격이 주어지는 똑똑한 팔로워 명단.

## min.insync.replicas
데이터 전송 성공을 인정받기 위해 최소한 몇 대의 복제본에 저장이 완료되어야 하는지 정하는 기준 숫자.

## 3. 데이터 송수신 파이프라인 (클라이언트 계층)

## 3.1 프로듀서 데이터 송신 메커니즘

## 메시지 키 (Message Key)
순서 보장이나 특정 파티션 지정을 위해 데이터에 함께 실어 보내는 고유 식별자.

## 직렬화 (Serializer)
내가 짠 자바 객체 코드를 네트워크로 던질 수 있게 바이트 배열로 변환하는 기술.

## 파티셔너 (Partitioner)
메시지 키를 수학적 공식에 대입하여 이 데이터를 몇 번 파티션으로 보낼지 최종 결정하는 장치.

## 3.2 프로듀서 내부 스케줄링 및 버퍼링

## 레코드 어큐뮬레이터 (Record Accumulator)
네트워크 오버헤드를 줄이기 위해 파티션별로 데이터를 잠시 가둬두는 대기실.

## 배치 (Batch)
대기실에 모인 데이터를 한 가득 묶어서 대량으로 전송하는 묶음 단위.

## linger.ms
대기실에서 데이터를 꽉 채울 때까지 기다려줄 수 있는 최대 시간 설정.

## 샌더 스레드 (Sender Thread)
메인 프로그램과 별개로 독립적으로 작동하며 대기실의 데이터를 브로커로 배달하는 백그라운드 일꾼.

## 3.3 전송 신뢰성 보장 장치

## acks
데이터를 브로커에 찔러 넣은 후 어느 단계까지 성공 신호를 받아올지 결정하는 프로듀서 핵심 옵션.

## 콜백 메서드 (Callback Method)
메인 프로그램을 멈추지 않고 배달원이 전송을 완전히 끝마친 직후 자동 실행되는 비동기 예약 코드.

## 3.4 컨슈머 데이터 수신 메커니즘

## 컨슈머 그룹 (Consumer Group)
하나의 목적을 위해 토픽을 나누어 읽는 컨슈머들의 독립적인 연합체.

## 파티션 독점 규칙
동일한 컨슈머 그룹 안에서 하나의 파티션은 오직 한 명의 컨슈머만 매핑되어 독점 소비해야 하는 규칙.

## 오프셋 (Offset)
컨슈머가 파티션 내부에서 데이터를 어디까지 읽었는지 나타내는 고유 번호.

## 4. 데이터 정시성 및 신뢰성 설계 (아키텍처 패턴 계층)

## 4.1 메시지 처리 보장 원칙

## 멱등성 (Idempotency)
동일한 연산이나 메시지를 100번 넘게 실행해도 결과가 오염되지 않고 항상 똑같은 상태를 유지하는 성질.

## 카프카 트랜잭션
카프카에서 데이터를 읽고, 가공해서, 다른 토픽으로 다시 쏠 때 전체 과정을 정확히 한 번으로 묶어주는 기술.

## 4.2 시스템 간 트랜잭션 보장 패턴

## 트랜잭션 아웃박스 패턴
내 DB 저장과 카프카 전송을 한 트랜잭션으로 묶어 메시지 유실을 완벽히 방지하는 송신단 설계 패턴.

## 인박스 패턴
수신한 메시지 ID를 DB에 기록하여 중복 메시지가 들어와도 처리를 씹어버리는 수신단 멱등성 보장 패턴.

## 4.3 데이터 변경 추적 기술

## CDC (Change Data Capture)
일반 쿼리 방식이 아니라 DB 최하단의 로그 파일을 실시간으로 훔쳐보고 변화를 감지하는 기술. 즉, 리스너를 통해서 DB 로그를 스트리밍하고 있다가 데이터 생기면 DB 엔진이 CDC에게 푸시해주고 CDC는 그것을 브로커에게 전송하기 위해서 레코드 어큐물레이터에 푸시함

## 빈로그 (Binlog / Binary Log)

MySQL DB 내부에서 데이터의 모든 생성/수정 이력을 가장 빠르고 가볍게 기록해 두는 일기장.
