## 1. 백엔드 무한 재시작 (Restarting) 해결

**증상:** `docker ps`를 하면 백엔드 컨테이너가 자꾸 죽었다 살아남 (`Restarting`).

**원인:** **DB 스키마 불일치.**

- JPA Entity(자바 코드)에는 `created_at` 컬럼이 있는데, Flyway SQL(DB 설계도)에는 빠져 있어서 `Schema-validation` 에러 발생.

### 해결
1. Flyway SQL 파일(`V...sql`)에 `created_at` 컬럼 추가.
    
2. 기존 데이터 충돌을 막기 위해 볼륨까지 삭제 후 재배포.
    
```Bash
docker compose -f docker-compose-prod.yml down -v
docker compose -f docker-compose-prod.yml up -d --build
```

### 2. 외부 접속 불가 (Connection Refused) 해결

**증상:** 서버는 켜졌는데 브라우저에서 `13.124.6.228:8080` 접속 시 연결 거부됨.

**원인:** **AWS 보안 그룹(방화벽) 차단.**

- 관리자가 8080번 포트는 막아놓고, 80번(HTTP 기본) 포트만 열어둠.

### 해결
- `docker-compose.yml`에서 포트 설정을 수정하여, 열려 있는 80번 구멍을 이용해 내부 8080번으로 연결함.

```YAML
# 수정 전
ports:
  - "8080:8080"
# 수정 후 (외부 80 -> 내부 8080)
ports:
  - "80:8080"
```
- **결과:** `http://13.124.6.228` (포트 번호 없이) 접속 성공.

### 3. 로컬 vs 배포 환경변수 충돌 해결

**증상:** 로컬 개발 시에는 `.env` 파일이 필요하고, 도커 배포 시에는 파일 없이 환경변수로 주입됨. 코드가 `.env` 파일이 없으면 에러(`return`)를 내고 죽음.

### 해결**
- `PresentationApplication.java`의 `main` 함수 수정.
- "파일이 존재할 때만(`if envFile.exists()`) 로드하고, 없으면 도커 환경변수를 믿고 진행한다"는 로직으로 변경.

### 4. 젠킨스(Jenkins) 설치 및 접속 (SSH 터널링)

**목표:** CI/CD 구축을 위해 젠킨스 설치.

**설치:** 프로젝트 폴더와 분리하여 홈 디렉토리(`~/jenkins`)에 설치함.

**문제:** 젠킨스 포트(**9090**)도 AWS 방화벽에 막혀 접속 불가.

### 해결 - **SSH 터널링 (개구멍 뚫기).**

- 내 컴퓨터(로컬)의 포트와 서버의 포트를 비밀 터널로 연결.
```Bash
# 내 컴퓨터 터미널에서 실행 (끄면 안 됨)
ssh -i "키파일.pem" -L 9090:localhost:9090 ubuntu@13.124.6.228
```
- **접속:** 내 컴퓨터 크롬에서 `http://localhost:9090`으로 접속하여 젠킨스 설정 완료.

### ✅ 현재 상태 요약

1. **백엔드 서버:** `http://13.124.6.228` (정상 작동, 누구나 접속 가능)
2. **젠킨스 서버:** `http://localhost:9090` (SSH 터널링 켠 상태에서만 접속 가능, 관리자용)
3. **코드:** 로컬/배포 어디서든 수정 없이 돌아가도록 세팅됨.
