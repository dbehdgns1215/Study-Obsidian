
## 1. 무중단 배포 파이프라인 핵심 흐름

우리 프로젝트의 무중단 배포는 `deploy.sh` 스크립트를 통해 Nginx의 `upstream`을 동적으로 교체하는 방식.

새 버전의 컨테이너를 띄우고 헬스체크가 통과되면 Nginx가 트래픽을 새 컨테이너로 전송하는 형태.

### 전체 흐름 요약

1. **컨테이너 내부 파일 읽기**
	- Nginx 설정에서 현재 활성화된(Active) 컨테이너 컬러(Blue 또는 Green)를 확인
2. **변수 세팅**
	- 새롭게 배포할 대기(Next) 컬러와 포트를 지정.
3. **신규 컨테이너 실행 및 헬스체크**
	- Next 컬러의 컨테이너를 띄우고 정상적으로 응답하는지 대기. (2분)
4. **Upstream 교체**
	- Nginx 설정 파일 내의 라우팅 주소를 신규 컨테이너로 치환.
5. **Nginx 리로드**
	- 기존 커넥션을 유지한 채 Nginx 설정만 다시 읽어 트래픽을 전환.
6. **구버전 컨테이너 중지**
	- 이전 버전의 컨테이너를 down.

## 2. 배포 스크립트(`deploy.sh`) 핵심 로직 분석


### 1. 활성 컬러 감지 (설정 파일 읽기)

현재 Nginx가 바라보고 있는 타겟이 Blue인지 Green인지 파악부터 함.

```Bash
CURRENT_UPSTREAM=$(docker exec $NGINX_CONTAINER grep -o 'playlist-backend-[a-z]*' /etc/nginx/nginx.conf | head -1)
```
- `docker exec playlist-nginx`: Nginx 컨테이너 내부에서 명령을 실행
- `grep -o 'playlist-backend-[a-z]*'`: 정규식에 매칭되는 문자열(`playlist-backend-blue` 등)만 추출
- `/etc/nginx/nginx.conf`: 대상 설정 파일
- `head -1`: 여러 줄이 나올 경우 첫 번째 줄만 가져오기

이를 통해 `CURRENT_UPSTREAM="playlist-backend-blue"` 값을 얻고, 이후 조건문을 통해 `ACTIVE=blue`, `NEXT=green`, `NEXT_PORT=8082`로 배포 변수를 자동 세팅

### 2. Upstream 교체 및 트래픽 전환 (설정 파일 수정)

헬스체크 통과 후, 실제로 트래픽을 전환하는 구간

```Bash
docker exec $NGINX_CONTAINER sed -i \
    "s/server playlist-backend-${ACTIVE}:${ACTIVE_PORT}/server playlist-backend-${NEXT}:${NEXT_PORT}/g" \
    /etc/nginx/nginx.conf
```
- `sed -i "s/찾을것/바꿀것/g"`: 파일 내부의 텍스트를 In-place 방식으로 교체
- 실행 결과 예시: `server playlist-backend-blue:8081` -> `server playlist-backend-green:8082`

이후 Nginx 리로드를 통해 설정값을 즉각 반영시킴.

```Bash
docker exec playlist-nginx nginx -s reload
```

> `reload` 명령은 프로세스를 재시작하는 것이 아니라 설정 파일만 다시 읽게 하므로 **기존 사용자들의 연결이 끊기지 않음.**

## 4. 트러블 슈팅 및 주의사항

### Issue 1. Jenkins 컨테이너에서 헬스체크(curl) 실패 이슈

- **원인:** Jenkins가 도커를 통해 독립된 컨테이너 환경에서 실행 중이어서, 백엔드 컨테이너가 속한 `app-network`(`172.19.0.x` 대역)로 직접 접근할 수 없는 네트워크 격리 문제가 발생했음.
    
- **해결:** 백엔드와 동일한 네트워크에 있는 Nginx 컨테이너를 경유하여 헬스체크를 수행하도록 수정했음. (`HTTP_STATUS=$(docker exec $NGINX_CONTAINER curl -s -o /dev/null -w "%{http_code}" --connect-timeout 3 "http://${NEXT_CONTAINER}:${NEXT_PORT}/actuator/health" 2>/dev/null || echo "000")`)
    
- **추가 조치:** 기본 `nginx:alpine` 이미지에는 `curl`이 포함되어 있지 않으니까 **Nginx Dockerfile에 `curl` 설치 구문을 반드시 추가**하여 이미지를 빌드해야함.

### Issue 2. Nginx 재시작 시 Upstream 초기화

- **상황:** Nginx 컨테이너가 재시작되면 Dockerfile에 의해 COPY된 원본 `nginx.conf`(`server playlist-backend-blue:8081;`)로 설정이 덮어씌워짐.
    
- **해결 및 안전성 보장:** Jenkins 파이프라인(Jenkinsfile)의 실행 순서가 이를 커버
    1. `nginx` 컨테이너 재시작 (blue로 초기화됨)
    2. `deploy.sh` 실행
    3. 스크립트가 "현재 blue"임을 감지하고 자동으로 "green"에 새 버전을 배포
    4. Nginx의 타겟을 다시 green으로 교체
- 따라서 Nginx 컨테이너가 재시작되어도 파이프라인의 순서가 보장되어 있으므로 **정상적으로 동작**함. Nginx.conf 원본 파일의 주석 라인은 배포 스크립트의 `sed` 명령어에 영향을 주지 않음


# 무중단 배포 오류 발견

무중단 배포시에 Nginx와 연결된 컨테이너들까지 재생성하는 문제 해결  

![[Pasted image 20260315015610.png]]

```  
// 1. 프론트 (Nginx) - 기존 방식 유지 (재시작 시간 짧아 다운타임 미미)  
sh "docker compose -f docker-compose.prod.yml pull nginx"  
sh "docker compose -f docker-compose.prod.yml up -d --force-recreate --no-deps nginx"
```
- `--force-recreate`는 `depends_on`으로 연결된 컨테이너까지 모두 재생성하는 문제가 있었음.  
- 따라서 Nginx 컨테이너를 다시 띄우는 과정에서 무중단이 깨지게 됨  
- 이를 `--no-deps` 옵션을 통해서 해결
