# HTTP 톰캣 스레드

## HTTP Worker Threads
- 톰캣 서버가 HTTP 요청을 처리하기 위해 보유한 스레드
- 스레드풀 기본값은 200개
- 프론트에서 보내는 요청을 처리함
- `http-nio-exec-1` 이런 식으로 로그 찍힘

## Acceptor 스레드
- TCP 요청이 오면 문 열어주는 스레드

## Poller 스레드
- 홀 매니저(요청 다 왔는지 감시하다가 워커 스레드한테 배정)

---
## 애플리케이션 스레드 (Spring App Threads)

## main 스레드
- `java -jar` 실행할 때 main 메서드를 실행시키는 가장 첫 번째 스레드를 개념적으로 부르는 말

## 비동기/스케줄러 스레드 (App Threads)
- @Async 스레드
	- 백그라운드를 처리하는 스레드
		- `task-1`, `task-2` 로 불림
- @Scheduled 스레드
	- 배치 작업 수행하는 예약 스레드
		- 톰캣 스레드랑 별개의 풀임
			- `ThreadPoolTaskExecutor`을 사용함.

---
## 라이브러리 스레드
- HikariCP Housekeeping 스레드
	- DB 커넥션 10개가 안 끊기고 유지되는지 30초마다 체크함
	- 기본 커넥션 풀 사이즈는 10, 시간은 30초
- Kafka/Redis 스레드
	- 메시지 큐나 캐시 쓸 때 사용되는 스레드

---
## JVM 시스템 스레드 (System Threads)
- GC 스레드 (Garbage Collector)
	- 안쓰는 객체 소멸시킴
- JIT 컴파일러 스레드
	- 자바 코드 기계어로 번역할 때 자주 쓰이는 코드 분석해서 최적화 시켜줌
- 기타
	- Signal Dispatcher
		- 외부 신호 감지
	- Reference Handler (청소부 조수)
	    - 수명이 다해서 메모리에서 날아갈 객체들의 참조 상태(Weak, Soft 등)를 깔끔하게 떼줌
	- inalizer 스레드 (유언 집행자)
	    - 객체가 죽기 직전에 마지막으로 실행해야 할 코드(`finalize()` 메서드)를 실행함
		    - (요즘은 성능 깎아먹는 주범이라 거의 안 쓰지만, JVM 안에는 여전히 살아있기는 함)
        
- **Attach Listener (내부 감사팀):**
    
    - 평소엔 자고 있다가, 형이 나중에 서버 장애 났을 때 터미널에서 `jstack`이나 `jcmd` 같은 명령어로 "야, 너네 지금 스레드 몇 개가 무슨 일해?" 하고 찌르면, 그걸 듣고 보고서(Thread Dump)를 쫙 뽑아주는 아주 고마운 놈이야.




# 프로메테우스/그라파나

## 메트릭(Metric) - "측정 항목"
- 측정 항목
	- 측정하려는 주제 그 자체
- `http_server_requests_seconds_count` (총 주문 건수)
- `hikaricp_connections_active` (현재 사용 중인 가스레인지 수)

## 인스턴스 (Instance) - "지점 1곳의 포스기"
- 프로메테우스가 데이터를 긁어오는 구체적인 타겟 주소 1개(`IP:Port`)
	- 도커 컨테이너를 3개 띄웠으면, 인스턴스도 3개가 됨 (예: `172.31.57.78:8081`)

## 잡 (Job) - "같은 역할을 하는 지점들의 묶음"
- 인스턴스들을 하나로 묶어주는 그룹 이름
	- 프로메테우스 설정 파일(`prometheus.yml`)에서 설정
- 예: 서버 3대가 다 백엔드 역할을 하면 이 3개의 인스턴스를 묶어서 `job="backend"`라고 부름
        

## 애플리케이션 (Application) - "브랜드명"
- 보통 스프링 부트 `application.yml`에 적어둔 프로젝트 이름
	- 예: `plys`
	- 모니터링 쿼리를 짤 때 "다른 잡다한 서버들 말고, 딱 `plys` 앱에서 나온 데이터만 줘!" 할 때 라벨(Label)로 씀

## 네임스페이스 (Namespace) - "거대한 상권 / 환경"
- 보통 쿠버네티스(k8s) 같은 데서 쓰는 가장 큰 울타리야. 망 자체를 논리적으로 쪼개버림
	- 예: `dev` (개발 서버 동네), `prod` (실제 운영 서버 동네).

## 메트릭 구조
```
http_server_requests_seconds_count{
	namespace="dev", # 가장 큰 울타리 치고
	application="plys", # 그 안에서 plys 프로젝트 찾고
	job="backend", # 그중 백엔드 역할하는 그룹 찾고
	instance="10...:8081" # 그 그룹의 1번 포스기 데이터만 줘!
}
```
