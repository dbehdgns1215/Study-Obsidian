# 헥사고날 아키텍처(Hexagonal Architecture) 핵심 요약

## 1. 계층 구조와 의존성 흐름 (Horizontal View)
가장 중요한 것은 **"모든 화살표(의존성)는 안쪽(Domain)을 향한다"**는 점이다.
Service는 Adapter를 절대 모른다. 오직 Port(인터페이스)만 안다.

```text
      [Presentation]            [Application]              [Infrastructure]
+------------------------+  +------------------------+  +------------------------+
|   1. Controller        |  |      2. Service        |  |      3. Adapter        |
|      (웹 요청)          |  |       (흐름 제어)       |  |      (실제 기술)       |
+------------------------+  +------------------------+  +------------------------+
| [누굴 가지고 있나?]    |  | [누굴 가지고 있나?]    |  | [누굴 가지고 있나?]    |
|                        |  |                        |  |                        |
| private UseCase;       |->| private LoadPort;      |<-| private JpaRepository; |
| (인터페이스)           |  | private SavePort;      |  | (진짜 DB 기술)         |
|                        |  | (인터페이스)           |  |                        |
|                        |  |                        |  | private Mapper;        |
|                        |  |                        |  | (변환기)               |
+------------------------+  +------------------------+  +------------------------+
| [하는 역할]            |  | [하는 역할]            |  | [하는 역할]            |
| "매니저(Service)님     |  | "포트(Port)야          |  | "네! 제가 포트 구현체  |
|  이거 처리해주세요"    |  |  데이터 좀 가져와라"   |  |  입니다. DB 뒤질게요"  |
+------------------------+  +------------------------+  +------------------------+
```

## 2. 계층별 핵심 역할 및 파일

### A. Domain Layer (가장 안쪽, 핵심)

- **역할:** 비즈니스 로직의 심장. 데이터와 행위(규칙)를 가짐.
    
- **특징:** 어떠한 프레임워크(Spring, JPA)에도 의존하지 않는 순수 자바 객체(POJO).
    
- **구성요소:**
    
    - `Entity`: 식별자(ID)가 있고 생명주기가 있는 객체. (예: `CoverLetter`)
        
    - `VO`: 값을 표현하는 불변 객체.
        

### B. Application Layer (중재자)

- **역할:** 비즈니스 흐름(Flow) 제어. 도메인 객체를 불러와 일을 시킴.
    
- **특징:** 외부(DB, Web) 구체적인 기술을 모름. 인터페이스(Port)로만 소통.
    
- **구성요소:**
    
    - `UseCase`: 외부(Web)에서 들어오는 요청 인터페이스. (In-Port)
        
    - `Port`: 외부(DB)로 나가는 요청 인터페이스. (Out-Port)
        
    - `Service`: `UseCase`의 구현체. `Port`를 호출함.
        

### C. Infrastructure Layer (기술 구현)

- **역할:** Application이 요구한 `Port`를 실제로 수행하는 기술 구현체.
    
- **특징:** 실제 DB(JPA), 외부 API 통신 코드가 위치함.
    
- **구성요소:**
    
    - `Adapter`: `Port` 인터페이스의 구현체.
        
    - `JpaEntity`: DB 테이블과 1:1 매핑되는 객체.
        
    - `JpaRepository`: Spring Data JPA 인터페이스.
        

### D. Presentation Layer (외부 접점)

- **역할:** 사용자 요청을 해석하고 응답을 포장함.
    
- **구성요소:**
    
    - `Controller`: HTTP 요청 수신, DTO 변환.
        

## 3. 핵심 규칙 (Golden Rule)

1. **Service는 Adapter를 import 하지 않는다.** (`Port`만 본다.)
    
2. **Domain은 아무것도 import 하지 않는다.** (순수성 유지.)
    
3. **Entity가 두 개다.** (Domain Entity vs Infra/Jpa Entity)
