
# 람다의 기본 형태

```java
(매개변수들) -> { 실행문 }
```

### 매개변수가 1개일 때 (소괄호 생략 가능)

```java
x -> System.out.println(x);
```

```java
(String x) -> System.out.println(x);
```

```java
x -> { System.out.println(x); }
```


## 매개변수가 2개 이상일 때 (소괄호 필수)

```java
(x, y) -> x + y
```

```java
(int x, int y) -> { return x + y; }
```

- 타입은 **컴파일러가 추론**함.
```java
(int x, int y) -> x + y   // 가능
(x, y) -> x + y           // 더 흔함
(int x, y) -> x + y       // 컴파일 에러
```

# 한 줄이면 `{}` + `return` 생략 가능

```java
() -> System.out.println("작업 중");
```

```java
(x, y) -> x + y;
```

- 여러 줄이면 `{}` 필수 + `return` 필요
```java
(x, y) -> {
    int sum = x + y;
    return sum;
}
```

# 람다는 **return 타입을 쓰지 않는다**

```java
interface Calc {
    int add(int a, int b);
}
```

```java
Calc c = (a, b) -> a + b;
```


# 람다를 쓸 수 있는 조건

```java
@FunctionalInterface
interface Runnable {
    void run();
}
```

```java
@FunctionalInterface
interface Consumer<T> {
    void accept(T t);
}
```

- 메서드가 2개 이상이면 람다 사용 불가능.

# 자주 사용하는 표준 함수형 인터페이스
|인터페이스|시그니처|의미|
|---|---|---|
|`Runnable`|`() -> void`|실행|
|`Consumer<T>`|`(T) -> void`|소비|
|`Supplier<T>`|`() -> T`|공급|
|`Function<T,R>`|`(T) -> R`|변환|
|`Predicate<T>`|`(T) -> boolean`|조건|


## this 차이 (익명 클래스 vs 람다)

```java
`this`
```
- 익명 클래스 → **자기 자신**
- 람다 → **바깥 클래스**


>람다는  
>“딱 하나의 추상 메서드”만 있을 때만 가능
>또한 “함수형 인터페이스의 단일 메서드를 간결하게 구현하는 문법”이다.



# Stream

```java
List<Integer> result =
    numbers.stream()
           .filter(n -> n % 2 == 0)
           .map(n -> n * 10)
           .toList();
```

```java
numbers
  → stream 열고
    → 조건 걸고(filter)
      → 변환하고(map)
        → 결과만 모아라(toList)
```

```
데이터 ──▶ filter ──▶ map ──▶ collect
```

```
함수형 프로그래밍
 → 함수(동작)를 값처럼 다룬다
   → 람다 = 그 표현 문법
     → 함수형 인터페이스 = 그릇
       → Stream = 그걸 실전에서 쓰는 무대
```


## 중간 연산 (Intermediate Operations)

> ✔️ **설정만 함**  
> ✔️ **Stream 반환**  
> ✔️ **여러 개 체인 가능**  
> ❌ 실행 안 됨 (lazy)

| 메서드        | 받는 함수형 인터페이스             | 뭐 하는 놈인지     |
| ---------- | ------------------------ | ------------ |
| `filter`   | `Predicate<T>`           | 조건으로 걸러냄     |
| `map`      | `Function<T,R>`          | 값을 다른 값으로 변환 |
| `flatMap`  | `Function<T, Stream<R>>` | 스트림을 평평하게    |
| `sorted`   | `Comparator<T>`          | 정렬           |
| `distinct` | 없음                       | 중복 제거        |
| `limit(n)` | 없음                       | 앞에서 n개만      |
| `skip(n)`  | 없음                       | 앞에서 n개 버림    |
| `peek`     | `Consumer<T>`            | 중간 확인 (디버깅용) |

---

### ✅ 중간 연산 예시

```java
numbers.stream()
       .filter(n -> n % 2 == 0)   // 짝수만 통과
       .map(n -> n * 10)          // 10배 변환
       .limit(3);                 // 앞에서 3개만

```

📌 **아직 아무 일도 안 일어남**


## 최종 연산 (Terminal Operations)

> ✔️ **실행 발생**  
> ❌ **Stream 반환 안 함**  
> ❌ **한 번만 가능**

|메서드|받는 함수형 인터페이스|뭐 하는 놈인지|
|---|---|---|
|`forEach`|`Consumer<T>`|하나씩 소비|
|`toList` / `collect`|`Collector`|모아서 컬렉션으로|
|`count`|없음|개수|
|`reduce`|`BinaryOperator<T>`|하나로 줄이기|
|`findFirst`|없음|첫 요소|
|`anyMatch`|`Predicate<T>`|조건 만족 하나라도?|
|`allMatch`|`Predicate<T>`|전부 만족?|
|`noneMatch`|`Predicate<T>`|전부 불만족?|

---

### ✅ 최종 연산 예시

```java
numbers.stream()
       .filter(n -> n % 2 == 0)
       .map(n -> n * 10)
       .toList(); // 🔥 여기서 실행
```


# 단계별로 보기

```java
List<Integer> result =
    numbers.stream()                // 1️⃣ 스트림 열기
           .filter(n -> n % 2 == 0) // 2️⃣ 조건 걸기
           .map(n -> n * 10)        // 3️⃣ 변환
           .toList();               // 4️⃣ 실행 + 수집
```

```
1번 요소 → filter → map → 저장
2번 요소 → filter → map → 저장
3번 요소 → filter → 탈락
```
- 필터로 걸러진 게 전부 한 번에 map으로 변환되는 게 아님.

# 자주 쓰는 표준 함수형 인터페이스들

| 인터페이스           | 시그니처             | 한 줄 요약 | 주 사용처         |
| --------------- | ---------------- | ------ | ------------- |
| `Runnable`      | `() -> void`     | 그냥 실행  | Thread        |
| `Consumer<T>`   | `(T) -> void`    | 받아서 소비 | forEach, peek |
| `Supplier<T>`   | `() -> T`        | 만들어서 줌 | lazy 생성       |
| `Function<T,R>` | `(T) -> R`       | 변환기    | map           |
| `Predicate<T>`  | `(T) -> boolean` | 조건 검사  | filter, match |
