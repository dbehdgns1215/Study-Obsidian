
기존의 함수를 보자.

```java
Thread t = new Thread(new Runnable() {  // ① 껍데기 시작
    @Override                           // ② 군더더기
    public void run() {                 // ③ 메서드 이름 명시
        System.out.println("작업 중");    // ✨ 진짜 핵심 알맹이 ✨
    }
});                                     // ④ 껍데기 끝
```
- 컴파일러 입장에서는 다음과 같이 생각할 수 있음.

> "야, `Thread` 안에는 어차피 `Runnable` 들어올 거잖아. 그리고 `Runnable` 인터페이스 까보니까 `run()` 메서드 딱 하나밖에 없던데? 굳이 `new Runnable()... public void run()...` 이렇게 구구절절 다 써야 돼? **그냥 알맹이(코드)만 주면 안 돼?**"

여기서 바로 **알맹이**만 넘기는 것이 바로 `함수형 프로그래밍`의 개념이고 그걸 표현하는 것이 바로 [[람다]]이다.



# 과정

`원본`
```java
new Runnable() {
    public void run() {
        System.out.println("작업 중");
    }
}
```

`어차피 Runnable 인거 알잖아?` (클래스명 삭제)`
```java
public void run() {
        System.out.println("작업 중");
    }
```

`메서드가 하나 뿐인데 이름이 뭔 상관?`
``` java
() {
        System.out.println("작업 중");
    }
```

`못생겼으니까 화살표 하나만 꼽자`
```java
() -> { System.out.println("작업 중"); }
```
