
## Prod .env 삽질 기록 & 최종 구조 정리

### 1) 무슨 일이었나

- 로컬/레포에는 `plys-backend/.env`, `plys-backend/infra/.env` 가 있고,
- Jenkins 쪽에는 `/var/jenkins_home/secret.env` + Jenkins 워크스페이스 `infra/.env` 가 따로 있었다.
- Spring Boot `application.properties` 에서는 `${ADMIN_EMAIL}`, `${ADMIN_PASSWORD}`, `${KAKAO_CLIENT_ID}` 등을 참조하는데,
  운영 컨테이너 안에서 `env | grep ADMIN`, `env | grep KAKAO` 를 찍어보면 **값이 전혀 없는 상태**였다.

증상:

- prod 백엔드가 부팅 시점에 아래와 같이 터졌다.

  > `Could not resolve placeholder 'ADMIN_EMAIL' in value "${ADMIN_EMAIL}"`

- `.env` 에는 분명히 `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NICKNAME` 가 있었는데도, 컨테이너 안에는 안 들어가 있었다.

---

### 2) 원인 정리

1. **Jenkins가 보는 .env와 내가 수정한 .env가 달랐다**
   - Jenkins `Deploy to Prod` 스테이지에서:
     - 예전에는 `cp /var/jenkins_home/secret.env ./.env` 로 secret.env를 워크스페이스에 복사한 후,
     - `docker compose --env-file .env ...` 을 실행했다.
   - 나는 EC2에서 `/home/ubuntu/workspace/S14P21B206/plys-backend/infra/.env` 만 수정하고 있었고,
     Jenkins가 실제로 쓰는 `/var/jenkins_home/workspace/plys/plys-backend/infra/.env` 는 옛날 값 그대로라,
     신규 `ADMIN_*`, `KAKAO_*` 가 prod에 반영되지 않았다.

2. **컨테이너 재생성을 하지 않으면 env 변경이 반영되지 않는다**
   - `env_file: .env` 는 **컨테이너를 만들 때** `.env` 내용을 복사해 넣는다.
   - 이후 `.env` 파일을 수정해도, 이미 떠 있는 컨테이너에는 자동으로 반영되지 않는다.
   - `docker compose up -d` 가 기존 컨테이너를 재사용하는 한, **env는 계속 옛날값으로 고정**된다.
   - 수동으로 `up -d --force-recreate` 를 때릴 때만 env가 새로 먹었다.

3. **env_file + environment 조합 자체는 문제가 아니었다**
   - 처음에는 `environment:` 때문에 `.env` 의 다른 키(ADMIN/KAKAO)가 “컷” 되는 줄 알았지만,
   - 실제 Docker Compose 동작은:
     - `env_file` 로 모든 키 로드 → `environment` 로 일부 키 override/추가
     - `environment`에 안 적힌 키를 지우지는 않는다.
   - 결론적으로, **구조 탓이 아니라 “어떤 .env로, 언제 만든 컨테이너냐” 문제가 원인이었다.**

### 3) 최종 해결: 단일 .env + 볼륨 마운트 + 강제 재생성

#### (1) 단일 소스 오브 트루스(SOT) 지정

- 운영용 `.env` 의 단일 기준을 다음으로 고정했다.

  - 호스트(EC2): `/home/ubuntu/workspace/S14P21B206/plys-backend/infra/.env`

- 이 파일만 수정하면 prod env 변경이 이루어지도록 설계를 맞춘다.

#### (2) Jenkins 컨테이너에 infra 디렉터리 볼륨 마운트

- Jenkins를 띄우는 Compose (예: `plys-backend/infra/docker-compose.jenkins.yml`) 에 다음 볼륨을 추가했다:

    jenkins:
      volumes:
        - /home/ubuntu/workspace/S14P21B206/plys-backend/infra:/workspace/S14P21B206/plys-backend/infra
        # ... 이미 있던 볼륨들 ...
