# 뱃지 - 여행 기록
- AI가 추천해준 장소 리스트
	- 장소 정보
- 여행 제목
- 여행 일자
- 방문한 지역 (시, 구)
- 총 개수 및 방문한 개수

```d
{
  id: string,              // 고유 ID
  title: string,           // 여행 이름
  regions: Array<string>,  // 여행 지역 배열 ["대전 동구", "대전 중구"]
  startDate: string,       // 여행 시작 날짜 (YYYY-MM-DD)
  endDate: string,         // 여행 종료 날짜 (YYYY-MM-DD)
  progress: number,        // 방문 완료한 장소 수 (자동 계산)
  total: number,           // 전체 장소 수 (자동 계산)
  places: Array<Place>,    // 여행 장소 목록
  status: string,          // 뱃지 상태 (not_started/in_progress/completed)
  color: string|null,      // 프로그레스 바 색상 (없으면 자동 계산)
  createdAt: Date,         // 생성 시간
  completedAt: Date|null   // 완료 시간
}
```

# 장소
- 장소명
- 장소 타입 (음식점, 카페, 관광지 등)
- 주소
	- 신주소, 구주소
- 방문 여부
- 영업 시간
- 전화번호

```d
  id: string,              // 장소 고유 ID
  name: string,            // 장소 이름
  type: string,            // 장소 타입 (음식점/카페/관광지 등)
  businessHours: string,   // 영업 시간
  closedDay: string|null,  // 휴무일
  visitDate: string|null,  // 방문 날짜 (null이면 미방문)
  visited: boolean,        // 방문 여부
  imageUrl: string|null,   // 장소 이미지 URL
  location: object|null,   // 위치 정보 (위도, 경도)
  address: string|null,    // 주소
  phone: string|null       // 전화번호
```

AI 질문 들어올거임 이게 진짜 중요할지도
- 일단 지금은 누구나 접근할 수 있는 공공데이터를 활용했고 AI 관련 기술들 좌라라락 나열했음
- AI 기술은 어쨌든 결제자도 만족을 해야하는 거잖아. 적합한 날짜 환승 시간 이런 것들이 전부 다 마음에 들어야 함. 어찌보면 시계열 예측임 LST. AI 딥러닝 기반의 LST 알고리즘을 적용해서 아직은 정확도가 x%지만 갈 수록 정교해진다. 우리는 사용자가 많으면 많을 수록 정확도가 더더욱 올라갈 것이다. 이렇게 하면 공격은 덜 당할 것 같은데 다른 기술을 하면 질문 들어올 수 있는 것들이 너무 많음.
- 추천 알고리즘은 2가지가 있음.
	- 컨텍스트 기반, 유저 기반 두 개가 있음.
	- 원래 어필은 선호도로 해서 데이터에 들어간 정보들이 있잖아 디스크립션 같은 것들 그것들로 벡터화해서 쿼리상으로 가장 가까운 것을 추천하지만 GPT가 대화가 쌓였을 떄 컨텍스트가 쌓일 수록 친근하게 느낄 수 있는 것처럼, 여행을 반복하면 반복할 수록 해당 사용자의 여행 기록을 서머라이징 해서 최적의 추천을 해줄 수 있또록. 사용하면 사용할 수록 더 개인화 더 고도화 되는 서비스라고 말하려고 했음 RAG 프롬프팅 오픈API는 짧게 넘어가고
	- 유저 데이터가 쌓이면서 나중에는 위와 같이 가려고 했으나 공격이 들어올 만한 요소들이 너무나도 많음..
	- 우리의 목적은 해커톤이니까. 공격적인 질문이 들어와 약점을 파고들어 그러면 사람들은 반박하거나 그러지마. 잘 듣고 그 부분에 대해서 보완하겠습니다. 알면 잘 말하면 되고. 보완하면 됨.
