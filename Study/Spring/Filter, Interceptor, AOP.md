### 2. 상세 비교 (공항 비유)

#### ① Filter (필터)

> **비유: 공항 검색대 (입구 컷)**
> 
> **위치: Web Container (Tomcat) 관리**

- **특징:** 스프링의 본거지(Spring Context)에 들어가기도 전에 실행됩니다.
    
- **하는 일:**
    
    - "이 사람 흉기(XSS 공격) 들고 있나?"
        
    - "한국어(UTF-8 인코딩) 쓸 수 있는 사람인가?"
        
    - **전역적인 보안(Spring Security)** 처리가 여기서 일어납니다.
        
- **오자작 적용:** "들어오는 모든 요청의 글자가 깨지지 않게 인코딩 필터를 건다."
    

#### ② Interceptor (인터셉터)

> **비유: 입국 심사관 (목적지 확인)**
> 
> **위치: Spring MVC 관리**

- **특징:** 스프링 안으로 들어왔고, **"어떤 컨트롤러(목적지)로 갈지"** 알고 있습니다.
    
- **하는 일:**
    
    - "너(User) 이 컨트롤러(자소서 수정)에 갈 자격 있어?" (로그인 체크)
        
    - "이 컨트롤러 처리하는 데 얼마나 걸렸지?"
        
- **오자작 적용:** "로그인 안 한 사람이 `/api/cover-letters`에 접근하면 쳐낸다." (JWT 검증 등)
    

#### ③ AOP

> **비유: 전담 수행비서 (밀착 케어)**
> 
> **위치: Spring Bean (Proxy) 관리**

- **특징:** URL이나 HTTP 요청 따위는 관심 없고, **"특정 메소드(행동)"**에만 관심 있습니다. 컨트롤러, 서비스, 리포지토리 어디든 붙을 수 있습니다.
    
- **하는 일:**
    
    - "사장님(Service)이 업무(메소드) 시작하면 트랜잭션 열어드려."
        
    - "업무 중 에러 나면 롤백해드려."
        
    - "입출금 메소드 실행될 때만 로그 남겨."
        
- **오자작 적용:** "`CoverLetterService.save()` 메소드가 실행될 때 트랜잭션을 건다."

### 3. 핵심 차이 요약표

|**구분**|**관리자(주관)**|**실행 시점**|**파라미터 접근**|**주 용도**|
|---|---|---|---|---|
|**Filter**|Web Container (Tomcat)|스프링 진입 전|`Request`, `Response` (Raw 데이터)|인코딩, 보안(XSS/CORS), 전역 로깅|
|**Interceptor**|Spring MVC|컨트롤러 호출 전/후|`Request`, `Response`, **`Handler(매핑 정보)`**|인증/인가, API 호출 시간 측정|
|**AOP**|Spring Framework|**메소드** 실행 전/후|**메소드의 파라미터, 리턴값**|트랜잭션, 예외 처리, 비즈니스 로깅|

### 결론: 왜 나눠 놨을까?

- **Filter:** "HTTP 요청 자체"를 뜯어고쳐야 할 때 씁니다. (스프링 기능 필요 없을 때)
    
- **Interceptor:** "Controller"에 넘겨주기 전에, **스프링의 도움(Bean 사용)**을 받아서 검사할 때 씁니다.
    
- **AOP:** "비즈니스 로직(Java 코드)" 사이사이에 끼어들어야 할 때 씁니다. (Controller랑 상관없이 Service단에서도 쓸 수 있음)
    

**동훈님 질문에 대한 정답:**

> "프론트에서 넘어올 때 **가장 먼저 만나는 건 Filter**이고, 그 다음 스프링 문 열고 들어와서 **컨트롤러 앞에 있는 게 Interceptor**, 그리고 **메소드마다 껌딱지처럼 붙는 게 AOP**입니다."
